# Event Check-In 活動管理與寄送功能增強設計

日期：2026-07-20  
狀態：已完成對話設計確認，待使用者審閱正式規格

## 1. 目標

在既有 React 18、Vite、JSX 與 React Context 架構內完成以下改造：

1. 所有需要選擇活動的頁面都能快速搜尋與篩選。
2. 自建活動支援自動平均分組與手動分組。
3. 教材管理支援勾選特定參加者後批次發送。
4. 問卷可設定活動前或活動後發送，並遵守時間與收件資格規則。
5. LMS 活動的參加者名單改由外部 LMS 網址查看及管理。
6. 活動基本資料加入課程建立人、課程描述，活動管理加入日期搜尋。

本次不更換框架、不新增大型狀態管理套件，也不串接真實公司 API；以 API-ready 的 mock service 與可測試 domain functions 完成展示。

## 2. 架構決策

延續目前的 React Context 作為活動與使用者介面狀態來源。新增兩類共用能力：

- `EventPicker`：所有活動選擇頁面共用的搜尋及篩選元件。
- Domain functions：處理活動篩選、手動分組驗證、問卷發送資格、收件人選擇及教材批次發送結果。

各頁面不再自行維護互不相干的活動清單。活動管理、教材管理、問卷、早鳥、抽獎、歷史紀錄與數據報表都從同一份 Context 活動資料衍生可選活動，避免出現未知活動或資料不同步。

## 3. 資料模型

### 3.1 Event

在現有 Event 模型加入：

- `creator`：課程建立人。
- `description`：支援四語系的課程描述；缺少翻譯時回退來源語言。
- `rosterUrl`：LMS 外部名單網址；自建活動可為空。
- `grouping.mode`：`none`、`automatic` 或 `manual`。
- `grouping.targetSize`：自動分組的每組目標人數。
- `grouping.assignments`：自建活動手動分組的人員與組別對照。
- `survey.timing`：`before` 或 `after`。

原有 `source`、LMS 分類、活動時間、狀態、模組設定與多語內容繼續保留。

### 3.2 Participant

沿用既有員工資料及 `group` 欄位。LMS 參加者仍會透過 mock LMS service 同步到標準模型，供智慧報到與數據報表使用，但不在活動管理頁提供名單瀏覽或編輯。

### 3.3 DeliveryRecord

沿用共用寄送紀錄模型，保存收件人、狀態、發送次數、最近發送時間及錯誤。批次操作必須逐筆回傳結果，不能因部分成功便把全部人員標記為成功。

## 4. 共用活動選擇器

所有「選擇現有活動」的情境改用共用 `EventPicker`，包含：

- 教材管理
- 問卷發送
- 早鳥福利
- 活動抽獎
- 歷史紀錄
- 數據報表
- 其他需要切換活動的管理頁面

`EventPicker` 提供：

- 活動名稱關鍵字搜尋。
- 來源、狀態、課程類型篩選。
- 月份與日期區間篩選。
- 清除全部條件。
- 無結果、載入失敗與安全重試狀態。

不同頁面可傳入額外限制：教材、問卷、早鳥與抽獎只顯示已啟用相應模組的活動；歷史紀錄只顯示已結束或已取消活動。初次進入頁面不自動選取第一個活動，使用者選擇後才載入該活動內容。

活動管理的「瀏覽現有活動」沿用相同搜尋核心，並加入日期或日期區間條件，讓 HR 可直接查找特定月份或日期的課程。

## 5. 活動基本資料

自建活動表單新增：

- 課程建立人：必填文字欄位。
- 課程描述：必填多行文字欄位。

從 LMS 選擇活動時，課程建立人與課程描述和其他 LMS 基本資料一併帶入並維持唯讀。使用者仍可依目前產品規則設定可選模組；LMS 的名單與分組則以 LMS 來源資料為準。

活動詳細資訊頁同步顯示課程建立人、課程描述與 LMS 名單連結狀態。

## 6. 分組設計

### 6.1 自建活動

自建活動提供三種選項：

1. 不分組。
2. 自動平均分組：HR 輸入每組人數，系統使用既有平均分配邏輯產生 A、B、C 等組別，避免最後一組與其他組人數差距過大。
3. 手動分組：在模擬名單或 CSV 名單載入後，HR 可逐一指定每位參加者的組別。

手動分組儲存前必須驗證：

- 每位參加者都有組別。
- 組別名稱去除前後空白後不可為空。
- 同一位參加者只能屬於一組。

若名單後續增減，新增且尚未分組的人員會被標示為待處理，活動更新前必須補齊。

### 6.2 LMS 活動

LMS 活動的分組模式與人員組別由 LMS payload 提供，Event Check-In 只讀取結果，不在活動管理頁提供手動修改。需要調整時，使用者必須透過外部 LMS 名單頁處理，後續再由同步資料更新。

## 7. LMS 外部名單

LMS 活動不在 Event Check-In 的活動管理頁顯示或編輯參加者名單，改為顯示「前往 LMS 查看／管理參加者名單」按鈕：

- 網址來自 `event.rosterUrl`。
- 使用新分頁開啟。
- 網址缺少或格式無效時按鈕停用，並清楚說明原因。
- 自建活動不顯示此按鈕，繼續提供模擬名單、CSV 上傳與範本下載。

智慧報到與數據報表仍需使用已同步到前端標準模型的 LMS 人員資料。這是背景資料用途，不代表活動管理頁重新提供 LMS 名單編輯功能。

## 8. 教材管理

每位參加者列前新增 checkbox，表頭提供三態全選 checkbox：

- 全選只作用於目前搜尋及篩選後可見的人員。
- 切換搜尋條件時，已選但暫時不可見的人員仍保留，直到使用者取消或完成發送。
- 畫面顯示目前已選人數。
- 「發送給已選人員」只傳送給勾選者。
- 保留個別重寄與「重寄給活動全部人員」。

批次結果處理：

- 成功者從勾選集合移除。
- 失敗者保留勾選，以便直接重試。
- 沒有選取人員時，按鈕停用並說明原因。
- Email 無效或寄送部分失敗時逐筆顯示結果，不提前寫入成功狀態。

## 9. 問卷發送

啟用問卷模組時，活動建立或匯入流程必須設定問卷網址及發送時機。

### 9.1 活動前發送

- `survey.timing = before`。
- 活動建立完成且問卷網址有效後即可手動發送。
- 收件人為該活動所有報名者。

### 9.2 活動後發送

- `survey.timing = after`。
- 活動預定結束時間以前，個別與批次發送按鈕都保持鎖定。
- 畫面顯示確切解鎖日期與時間。
- 到達活動結束時間後，收件人只包含至少有一次成功 Check-in 的參加者。

共用 domain function 負責判斷：

- `canSendSurvey(event, now)`：是否已符合發送時間。
- `getSurveyRecipients(event, participants, attendanceRecords)`：依活動前／後規則取得收件人。

UI 與 service 呼叫前都使用相同規則驗證，避免只鎖住畫面但底層仍可錯誤觸發。沒有符合資格的收件人、缺少問卷網址或網址無效時，不執行寄送並顯示原因。

## 10. 多語系與介面狀態

新增欄位、按鈕、驗證、空狀態及錯誤訊息全部提供繁體中文、簡體中文、英文與日文。LMS 動態文字缺少翻譯時依既有規則回退來源語言。

延續藍白色極簡視覺與目前的響應式版面。搜尋及篩選控制保持一致的焦點樣式，不新增突兀的色彩或持續存在的通知。

## 11. 例外處理

必須處理：

- 活動搜尋無結果、載入逾時、API 失敗及日期區間前後顛倒。
- LMS 名單網址缺少、格式無效或外部頁面無法由系統驗證。
- 手動分組不完整或名單變更後出現未分組人員。
- 教材未勾選收件人、Email 無效與批次部分成功。
- 問卷尚未解鎖、網址缺少、無合資格收件人與批次部分成功。
- 工作階段失效與離線狀態。

所有非成功結果都不得預先更新為成功；可重試操作應保留使用者目前的搜尋、篩選與失敗項目選取狀態。

## 12. 測試策略

沿用現有 Node 測試架構並採測試先行：先建立會因缺少功能而失敗的測試，再完成最小實作。

Domain tests 覆蓋：

- 活動名稱、來源、類型、狀態、月份及日期區間篩選。
- 模組與歷史狀態限制。
- 自動平均分組結果與手動分組驗證。
- LMS 外部名單網址判定。
- 教材選取、篩選後全選及部分失敗後的選取集合。
- 問卷活動前／活動後的時間限制與收件人資格。

整合與人工驗證覆蓋：

- 所有頁面共用相同活動來源，不出現未知或不同步活動。
- 自建活動可編輯，LMS 基本資料、名單及分組規則符合唯讀邊界。
- 四語切換後新增文字完整更新。
- 鍵盤操作、焦點、空狀態與錯誤重試。
- 完整 Node 測試與 Vite production build。

## 13. 驗收條件

本功能在以下條件全部成立時視為完成：

1. 每個活動選擇頁面都能以名稱及指定條件搜尋，且清單來源一致。
2. 活動管理能以日期查找活動，並顯示課程建立人與課程描述。
3. 自建活動可選不分組、自動平均或手動分組，且不完整手動分組不能儲存。
4. LMS 活動可透過有效外部網址前往 LMS 管理名單，Event Check-In 不提供 LMS 名單編輯。
5. 教材能對勾選人員批次發送，全選範圍與部分失敗處理符合規格。
6. 活動後問卷在結束時間前無法發送，解鎖後只寄給成功 Check-in 人員；活動前問卷寄給所有報名者。
7. 所有新增功能具備四語文字、錯誤狀態與安全重試。
8. 既有測試、新增測試及 production build 全部通過。
