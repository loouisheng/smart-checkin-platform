# 換皮整合作業手冊(把系統換成公司初版 UI)

> 目標:**保留這套系統的所有功能(引擎不動),只把外觀換成公司初版的設計。**
> 初版與現版的**版面、選單位置差不多**,差別主要在**顏色、字型、樣式** → 這是「換皮」,不是重寫。

---

## 0. 一分鐘看懂整體策略

- 你**不是**把功能塞進初版的 HTML(那是靜態設計稿,沒有邏輯,塞不進去)。
- 你是**把初版的「設計」套到這套會動的系統上**。
- 90% 的工作是改 **CSS**(顏色/字型/圓角/陰影),少數才動 `Shell.jsx` 的框架。
- **邏輯層一行都不要碰**(見第 5 節的「紅線清單」)。

### 兩條路線,先決定走哪條

| 路線 | 在哪做 | 適合 | 說明 |
|---|---|---|---|
| **A. 混合(建議)** | 公司只做「萃取」,回家做「套用」 | 你能把 `03-design-spec.md` 填好並 `git push` | 在公司花 1~2 小時抄下色碼/字型/截圖,填好規格表推上 GitHub,回家再實際改 CSS(環境舒服、可請 AI 協助) |
| **B. 全程在公司** | 公司做完全部 | 公司不准把任何數值帶出 | 用內網 clone、npm、公司內部 AI,在公司改完並 push |

> **強烈建議走 A。** 換皮真正花時間、需要反覆對照的是「套用」,在家做最快;而「萃取」只是照著初版抄數字,在公司很快。

## 1. 出發前的準備(在家先做好)

因為**不能用 USB**,所有東西都透過 **GitHub + 內網** 進出:

- [ ] **確認 repo 可在公司內網 clone**:`https://github.com/loouisheng/smart-checkin-platform`
- [ ] **申請一組 GitHub Personal Access Token(PAT)** 並記在安全的地方 —— 之後在公司 `git push` 會用到(公司電腦不會有你的登入)。
      GitHub → Settings → Developer settings → Personal access tokens → 產生一組有 `repo` 權限的 token。
- [ ] **把這三份文件讀熟**:本檔、`02-prompts.md`、`03-design-spec.md`。
- [ ] 記住:回家要用的東西 = **填好的 `03-design-spec.md`(+ 截圖,若公司允許)**。這就是你要「帶回來」的全部。

> 完全不需要帶硬體,也不需要把初版檔案帶出。你只帶「數字與筆記」,而且是透過 git 傳,不用 USB。

## 2. 到公司:把專案跑起來

```bash
# 1) 用內網取得專案
git clone https://github.com/loouisheng/smart-checkin-platform.git
cd smart-checkin-platform

# 2) 安裝相依套件(需要內網能連到 npm)
npm install

# 3) 啟動,瀏覽器開 http://127.0.0.1:5173 或終端機顯示的網址
npm run dev
```

同時用**另一個瀏覽器分頁打開公司初版 `reference.html`**,兩邊並排 → 這是你整個作業的「對照工作台」。

### ⚠️ 如果 `npm install` 失敗(內網連不到 npm)

依序試,任一成功即可:

1. **改用公司內部 npm 鏡像**(問 IT 有沒有內部 registry):
   ```bash
   npm config set registry <公司內部 registry 網址>
   npm install
   ```
2. **用 pnpm / yarn**(若公司電腦剛好有):`pnpm install` 或 `yarn`。
3. **完全裝不了套件 → 走「純比對」模式**:
   - 你**無法重新編譯 React**,但可以只做**萃取**:用第 3 節的方法把初版設計抄進 `03-design-spec.md`。
   - 預覽現版系統改用**免安裝的單檔版**:專案裡 `deliverables/smart-checkin-demo.html`,**雙擊就開、免 npm、免網路**,拿來跟初版並排看差異。
   - 這種情況請直接走**路線 A**:在公司只填規格表 → push → 回家做套用。

### ⚠️ 如果連 Node.js 都沒有、也裝不了

- 你不能跑 dev server,也不能 build。**只做萃取**(第 3 節用瀏覽器 F12,完全不需要 Node)。
- 一律走路線 A,回家再套用。

---

## 3. 萃取:把初版的設計「抄下來」

**主要工具是瀏覽器內建的開發者工具(F12),不需安裝任何東西、完全離線、給你精準數值。** 公司內部 AI 只是加速用的輔助。

打開初版 `reference.html`,按 **F12** → 用左上角的「選取元素」箭頭點畫面上的東西,右側 **Computed / Styles** 面板就會顯示精準的:

- `color` / `background-color` → 色碼(直接複製 hex)
- `font-family` → 字型
- `border-radius` → 圓角
- `box-shadow` → 陰影
- `padding` / `gap` / `font-size` → 間距與字級

**照著 `03-design-spec.md` 的每一格,把值填進去。** 重點抓這幾個:

1. **主色**(按鈕底色、連結色、重點色)
2. **主色-深**(hover、重點文字)
3. **文字色**(主要深色、次要灰色)
4. **背景**(整頁底色、卡片底色)
5. **邊框線色**
6. **字型**(中文 + 英文)
7. **圓角**(按鈕、卡片)
8. **陰影**(卡片有沒有陰影?深不深?)
9. **側邊欄**(深色底還是白底?選單選中時長怎樣?)

> **若允許截圖**:把初版的「報到頁、活動列表、活動表單、報表」各截一張,回家對照最準。截圖存進專案 `docs/reskin/shots/` 一起 push。

### 用公司內部 AI 加速(選用)

如果公司有內部開源模型(聊天介面),把初版 `reference.html` 的原始碼貼進去,用 `02-prompts.md` 的 **Prompt A**,讓它幫你一次輸出整份設計規格。**但一定要用 F12 抽查幾個色碼核對**,開源小模型偶爾會猜錯。

## 4. 套用:把規格改進系統(路線 A 回家做 / 路線 B 在公司做)

改動集中在 `src/v3/` 底下的 CSS。**一次改一小塊,每改一段就存檔看瀏覽器**(dev server 會自動刷新),和初版對照。

### 步驟 4-1:全域換色(影響最大,先做)

用 `03-design-spec.md` 最下方的**「換色對照表」**。做法是「找 → 替換」:把目前的色碼,全部換成初版對應的色碼。

- 在編輯器(VS Code)按 `Ctrl+Shift+H`(整個資料夾找替換),範圍限定 `src/v3`。
- 一次換一個色碼,例如把所有 `#2563eb` 換成初版主色。
- 表裡每一列都做一次。做完整體顏色就八成對了。

> 若公司有 AI:把某個 `.css` 檔 + 對照表貼給它,用 **Prompt B** 讓它產生改好的檔或找替換清單。**一次只餵一個 CSS 檔**(開源模型 context 有限)。

### 步驟 4-2:字型

- 改 `src/v3/styles.css` 最上面的 `:root { font-family: ... }`,換成初版的字型。
- 若初版用特定字型檔,而且要離線也顯示一致,再回報我,我教你內嵌。

### 步驟 4-3:圓角 / 陰影 / 框架微調

- 圓角、陰影多半也在各 CSS 檔,對照初版調。
- 側邊欄、頂欄的樣式在 `src/v3/styles.css` 開頭(`.ec-sidebar`、`.ec-topbar`)。因為版面本來就相近,通常只需微調顏色。

### 步驟 4-4:逐頁對照收尾

按頁面一頁一頁跟初版比對、微調。各頁面對應的檔案見 `03-design-spec.md` 的「畫面 ↔ 檔案對照表」。

## 5. 🚩 紅線:這些檔案不要改(改了會壞掉功能)

只要**碰邏輯層,系統就可能出錯**。換皮完全不需要動它們:

- `src/v3/domain.js`、`roster-domain.js`、`survey-domain.js`、`delivery-domain.js`(核心計算:報到、完訓、抽獎…)
- `src/v3/context.jsx`(狀態管理)
- `src/v3/xlsx.js`(Excel 產生)
- `src/v3/data.js`(示範資料)
- `src/v3/i18n.js`(多語文字 —— 除非要改字,否則別動)

**你只該動**:所有 `*.css`、`Shell.jsx`(框架/導覽),以及各頁面 `.jsx` 的**排版結構**(只有在版面真的不同時才需要)。

## 6. 驗證與送回成果

```bash
# 每完成一小塊就先確認沒壞
npm test          # 邏輯測試,應全部 ok
npm run build     # 能成功 build 代表沒有語法錯誤
```

送回成果(把改好的推回 GitHub,回家 pull):

```bash

git commit -m "style: 套用公司初版 UI 設計"
git push https://<你的PAT>@github.com/loouisheng/smart-checkin-platform.git main
```

### ⚠️ 如果公司不能 push 到 GitHub

- 走**路線 A**:你在公司**只需要 push 一個 `03-design-spec.md`**(純文字,體積小),或甚至把填好的規格表**內容貼進內網信箱寄給自己**。套用作業回家做,根本不用把整包程式帶出。
- 這也是為什麼建議路線 A —— 幾乎不依賴「能不能把程式帶出公司」。

## 7. 一頁流程總覽

```
在家:申請 GitHub PAT、讀三份文件
  ↓
公司:git clone → npm install → npm run dev(裝不了就用單檔版比對)
  ↓
公司:F12 抄初版設計 → 填 03-design-spec.md(+截圖)→ push
  ↓
(路線A)回家:pull 規格表 → 改 CSS 換色/字型/圓角 → npm run dev 對照 → build/test → push
(路線B)公司:同上,在公司做完 → push
  ↓
完成:系統功能全在,外觀變成公司初版
```
